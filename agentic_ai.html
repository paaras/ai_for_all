What an agent is

An agent is a language model that has been given tools and keeps working until a job is finished. It's the same kind of model you chat with.

If you ask a chat model to plan a Saturday, it writes a list of ideas. An agent checks the weather, looks up real places, finds their opening hours and prices, and gives you a finished plan.

Limits of a chat model

A chat model writes a single answer and stops. It has no way to look anything up or to test what it wrote, and it loses track of a very large job.

An agent gets tools for looking things up, a loop for testing its work, and helper agents for splitting up a large job.

How a model uses a tool

A language model can only write text. It has no way to open a web page or check the weather by itself.

A tool is something the app can do for the model. The model writes a short request that names the tool, the app runs it, and the result is added to the conversation as text for the model to read.

Tools that read and tools that act

Some tools only read things, like searching the web or opening a page. A mistake with these tools gives you a wrong answer, but it doesn't change anything.

Other tools change things, like sending an email or making a payment. A mistake with these can't always be undone, so give an agent only the tools it needs.

      The agent loop

      After the agent uses a tool, it reads the result and decides what to do next. It might use another tool, or it might decide it has enough to answer.

      This cycle is called the agent loop, and it repeats until the job is done. A simple job might take three trips around the loop, and a big job can take hundreds.

      What happens when a step fails

      Tools often fail, for example when a page won't load or a search doesn't return anything useful.

      The error comes back to the agent the same way any result does. The agent reads it and tries something different, like opening the next link when the first link is broken.

      The context

      The context is all the text the model can see while it works. It starts with the instructions and your task, and every tool result gets added to it.

      The model reads the whole context again at every step. On a long job the context grows, and the agent gets slower and starts to lose track of things from the beginning.

      What the agent knows

      An agent knows what it learned in training and what is in its context. It doesn't know your budget, where you live, or what you told another chat yesterday.

      If the agent needs to know something about you or the job, you have to write it in the task or the description.

      Using several agents

      A large job can be divided between several agents. A lead agent splits the job into parts and gives each part to a helper agent, and each helper starts with its own empty context.

      The helpers do the reading and send back short reports. The lead only reads the reports, so its context stays small enough to keep track of the whole job.

      Handing work to a helper

      A helper doesn't see the original task. The only thing it knows is the message the lead wrote for it.

      If that message is vague, the helper has to guess what's wanted. A good handoff says exactly what to find and what to send back.

      When to use an agent

      An agent is useful when a job takes many steps, needs information from outside the model, and has a result you can check.

      For a quick question, a chat is usually faster and less likely to make a mistake.

      Writing the description

      You design an agent by writing its description. The agent reads it before it starts, and it's the only explanation of the job the agent gets.

      A description should state the agent's job, explain how it should work and check its work, and describe the finished result.

        A team that works in order

        Another way to use several agents is to put them in a line. Each agent does part of the job and passes its work to the next agent.

        The last agent is often a checker. It starts with an empty context and reads the work for the first time, so it can catch mistakes the writer missed.

        Why long jobs go wrong

        Each step an agent takes has a small chance of being wrong, and later steps build on earlier steps. The more steps a job has, the more likely it is that a mistake happens somewhere.

        If an agent gets each step right 95% of the time, it will finish a 20 step job without a mistake only about a third of the time, so longer jobs need more checking.

        When an agent should ask first

        An email can't be taken back after it's sent, and a deleted file may be gone for good.

        Most agents can be set to ask for permission before certain actions. Let an agent read and write drafts without asking, and have it ask before it sends, buys or deletes anything.

        Prompt injection

        An agent reads a web page as plain text, and it can't always tell the page's text apart from your instructions. Someone can hide instructions in a page, and the agent may follow them.

        This is called prompt injection. When Anthropic tested its browser agent in 2026, hidden instructions worked about 3 times out of 10 before the safety features were turned on.
